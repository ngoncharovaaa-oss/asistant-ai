# AsiStantAI — ИИ-помощник руководителя

Второй «я» руководителя подразделения онлайн-продаж: разбирает входящую почту, готовит ответы от первого лица в его стиле, собирает протоколы встреч и утренний план, а всё чувствительное оставляет человеку. Ничего не отправляется без подтверждения.

Кейс «ИИ-помощник руководителя», трек «Цифровой аватар», хакатон «ИИкузница» 2026.

Работает офлайн на синтетическом датасете организаторов: детерминированные правила разбора, без внешних API и без ключей. Тот же датасет — источник всех цифр в презентации, поэтому код и защита считают одно и то же.

## Быстрый старт

Нужен Python 3.12 и пакеты из `requirements.txt`.

На Windows проще двойным кликом: `Запустить AsiStantAI.bat` — проверит Python, при необходимости поставит зависимости, поднимет сервер и откроет дашборд в браузере.

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows; на Linux/macOS — source .venv/bin/activate
pip install -r requirements.txt

python -m app.cli run           # разобрать неделю, собрать черновики и отчёты
python -m app.cli serve         # дашборд на http://127.0.0.1:8000
pytest                          # 35 проверок движка, API и живых каналов
```

Живые каналы включаются файлом `.env` (см. `.env.example`), код при этом не меняется:

```bash
python -m app.cli channels --check   # проверить вход в IMAP/SMTP, бота и Zoom
python -m app.cli run --live         # забрать новые письма из ящиков
python -m app.cli tg-listen          # принимать команды и кнопки бота
python -m app.cli zoom-link --topic "Планёрка" --start "2026-11-28 10:00"  # ссылка на встречу
```

`run` пишет результаты в `out/`, а состояние — в `data/asistant.db`. Дашборд читает журнал и при первом открытии сам досчитывает неделю, если журнал пуст.

## Как принимается решение

Порядок правил в `app/classify.py` — от жёсткого к мягкому:

1. **Чувствительная тема → «спросить руководителя».** Деньги и бюджеты, кадры, обязательства клиентам, письма руководству, стратегия, 1:1. Это ограничение не отключается настройкой: после классификации `app/pipeline.py` ещё раз проверяет риски и принудительно ставит эскалацию.
2. **Есть адресат в оргструктуре и тема в его зоне → «делегировать»** с конкретным человеком и причиной.
3. **Типовой запрос с готовым ответом в базе знаний → «авто»** (черновик готов, но отправка всё равно за человеком).
4. **Информационное письмо без действия → «игнорировать»**, статус для команды → «в сводку».

Каждое решение получает уверенность; ниже `CONFIDENCE_THRESHOLD` черновик не готовится.

## Черновики и обучение

`app/compose.py` собирает текст от первого лица по профилю руководителя: обращение, суть, срок, подпись. У каждого черновика — ссылки на источники: письмо, база знаний, встреча, задача, оргструктура.

Правка в дашборде (`POST /api/drafts/{id}/edit`) сохраняется в журнал и становится образцом для этой темы: следующие черновики той же темы собираются по исправленному тексту. Обучение — без дообучения модели и без кода.

Утверждение (`approve`) — единственная точка «отправки». На демо-датасете это мок: черновик помечается утверждённым, событие пишется в журнал, наружу ничего не уходит. На живом прогоне (`run --live`) утверждённый черновик реально уходит через SMTP того ящика, откуда пришло письмо. Отклонённый черновик утвердить нельзя.

## Протоколы встреч

`app/meetings.py` разбирает пять разных форматов конспектов: чек-листы задач, решения, открытые вопросы, ответственных (в том числе «Яне и Саше», «Speaker 2», «Маша и Ваня») и сроки («до 15.12.2026», «к следующему спринту»). Результат — 37 поручений и 16 открытых вопросов, файлы в `out/protocols/`.

Поручение попадает в календарь только после человека: в дашборде у каждой задачи есть «В задачи», у протокола — «Утвердить все». Статусы хранятся в журнале, каждое действие пишет событие; в демо календарь не трогается.

### Дожим поручений

После постановки задача живёт дальше: «В работу», «Решён» или «Не решён» с обязательной пометкой, что именно осталось. Решённые и нерешённые вопросы считаются отдельно — по протоколу и по неделе, — а протокол закрывается, когда все задачи либо решены, либо явно оставлены открытыми.

Если по ходу задача поменялась, её текст, исполнителя и срок правят прямо в строке. Правка сохраняет прежнюю формулировку в истории, требует причину и помечается «ждёт синхронизации». Кнопка «Синхронизировать» фиксирует, что руководитель в курсе: в живом режиме (`run --live`) уходит уведомление в Telegram, в демо — событие в журнале с каналом `mock`. Пока синхронизации нет, задача в дашборде подсвечена.

Составную задачу можно разложить на шаги по исполнителям — аналитик, BDM, команда CJM, смежные службы. У каждого шага свой срок, роль и зависимости: шаг без зависимостей стартует параллельно, шаг с зависимостями ждёт готовности указанных шагов и не открывается, пока они не закрыты. Для типовых сценариев («вендоры к продвижению», «витрина конкурентов», «метрики к сроку») в интерфейсе есть готовые наборы шагов с последовательностью и параллельными ветками.

## Утренний план и дайджест

`app/digest.py` собирает день руководителя: защищённые встречи и часы, решения, которые ждут именно его, дедлайны команды. Дайджест недели: сколько писем прошло без руководителя, что делегировано и кому, риски по срокам, итоги протоколов.

## Дашборд

`python -m app.cli serve` — http://127.0.0.1:8000, тёплая светлая тема, без внешних зависимостей.

- Карточки KPI: писем, черновиков, автоотправок, решений на руководителя, точность.
- Очередь черновиков с фильтрами «Все / Решение / Делегировано / Авто» и поиском по теме, адресату и тексту: утвердить, поправить на месте, отклонить.
- Панели: утренний план, дайджест, экономика, журнал, протоколы, полный разбор входящих со сверкой с эталоном.
- Протоколы: поручения утверждаются по одному или все сразу — со статусом «в календаре», отдельной панелью «Календарь» и записью в журнал. Дальше — «В работу» / «Решён» / «Не решён» с пометкой, правка текста, исполнителя и срока с историей и синхронизацией с руководителем, разложение задачи на шаги аналитика, BDM и CJM с последовательными и параллельными зависимостями.
- Журнал выгружается в CSV по ссылке «CSV» в панели.
- Панель «Каналы»: состояние ящиков А/Б, Telegram и Zoom, кнопка «Проверить» — вход в IMAP/SMTP, `getMe` бота и доступ к Zoom API. Кнопка «Живой прогон» снимает новые письма из IMAP. Панель «Zoom» создаёт ссылку на встречу (API или постоянная ссылка) с копированием в один клик.
- Переключатель профиля: второй руководитель подключается файлом, без изменений в коде.

API: `GET /api/health`, `GET /api/profiles`, `POST /api/run` (`source: "live"` — IMAP), `GET /api/summary`, `GET /api/drafts`, `GET /api/drafts/{id}`, `POST /api/drafts/{id}/edit`, `POST /api/drafts/{id}/approve`, `POST /api/drafts/{id}/reject`, `GET /api/protocols`, `POST /api/protocols/{id}/tasks/{index}/approve`, `POST /api/protocols/{id}/approve`, `POST /api/protocols/{id}/tasks/{index}/state`, `POST /api/protocols/{id}/tasks/{index}/revise`, `POST /api/protocols/{id}/tasks/{index}/sync`, `POST /api/protocols/{id}/tasks/{index}/steps`, `POST /api/protocols/{id}/tasks/{index}/steps/{step}/state`, `GET /api/calendar`, `GET /api/channels`, `POST /api/channels/check`, `POST /api/zoom/meeting`, `GET /api/metrics`, `GET /api/economics`, `GET /api/journal`, `GET /api/journal.csv`.

## Второй руководитель без кода

Профиль — Markdown-файл в `profiles/`: роль, стиль, правила делегирования, чувствительные темы, подпись. `profiles/leader2.md` — пример «Мария Орлова, коммерческий директор».

```bash
python -m app.cli run --profile profiles/leader2.md
```

Или выбрать профиль в шапке дашборда и нажать «Пересобрать неделю». Код не меняется.

## Живые почта, Telegram и Zoom

`app/live.py` — адаптеры без внешних зависимостей: `imaplib`, `smtplib` и Telegram Bot API через `urllib`. Всё выключено, пока в `.env` пусто; демо на датасете работает как раньше.

**Почта.** В `.env` заполняются `MAIL_A_IMAP_HOST`, `MAIL_A_SMTP_HOST`, `MAIL_A_USER`, `MAIL_A_PASSWORD` и, при необходимости, такой же блок `MAIL_B_*`. Порт 465 — SSL, иначе STARTTLS. Живой прогон забирает последние `MAIL_FETCH_LIMIT` писем из INBOX, пропускает уже виденные (таблица `seen_messages` в журнале), разбирает их тем же конвейером и отмечает UID прочитанными только после успешного прогона. Письма от собственного адреса пропускаются.

**Отправка.** Утверждение живого черновика отправляет письмо через SMTP того ящика, откуда пришло исходное письмо: ответ клиенту — с адреса руководителя, письмо из ящика Б — с ящика Б. Черновик-решение (эскалация самому руководителю) письма не имеет: он просто утверждается и уходит уведомлением в Telegram. Если для делегирования нет адреса в `data/kuznitsa/contacts.csv` (колонки `name,email`), черновик утверждается без отправки с пометкой причины. Ошибка SMTP не помечает черновик утверждённым — его можно повторить.

**Telegram.** Бот принимает `/status`, `/drafts`, `/approve <id>`, `/reject <id>`, а в `/drafts` — inline-кнопки «Утвердить»/«Отклонить». Команды выполняются только из чатов allow-list (`TELEGRAM_ALLOWED_CHATS`, по умолчанию — `TELEGRAM_CHAT_ID`); `/start` и `/id` отвечают любому и показывают его `chat_id`, чтобы было что внести в allow-list. Уведомления: итог живого прогона и факт отправки письма. Запуск слушателя — `python -m app.cli tg-listen`, остановка — Ctrl+C.

**Zoom.** Два режима без новых зависимостей: постоянная ссылка `ZOOM_PERSONAL_LINK` (работает сразу, без сети) или Server-to-Server OAuth (`ZOOM_ACCOUNT_ID`, `ZOOM_CLIENT_ID`, `ZOOM_CLIENT_SECRET`) — тогда создаётся новая встреча с ожиданием в зале, без записи и без host-ссылки наружу. Ссылка создаётся человеком: кнопкой «Создать ссылку» в дашборде, командой `zoom-link` или `POST /api/zoom/meeting`; событие пишется в журнал. Автоматических приглашений нет — письмо со ссылкой уходит только как обычный черновик после утверждения.

Секреты читаются только из `.env` и никуда не выводятся: ни в `/api/channels`, ни в журнал, ни в текст ошибок. В архив `.env` не попадает, в поставке только `.env.example`.

## Ограничения и этика

Текстовый помощник без клонирования голоса и лица. Отправка — только после подтверждения человеком: автоотправок нет ни в демо, ни в живом режиме. Чувствительные темы (деньги, кадры, обязательства перед клиентами, письма руководству) автоматизации не подлежат. Персональные данные в датасете синтетические. Живые IMAP/SMTP, Telegram и Zoom включаются только явным заполнением `.env`; без него система работает офлайн и ничего не отправляет. Zoom-ссылка создаётся по действию человека, host-ссылка (`start_url`) не сохраняется и не показывается.
